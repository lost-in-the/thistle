Amend diagnostic count and admission semantics: static capture coalesces only
identical known recoverable `dynamic_scope` warnings. Declaration-owner and
mixin-owner reasons, source paths and every additional provenance field remain
distinct. Each new record carries exact positive `occurrences`; an old record
without that field implies one. Consumers must count retained records as groups
and sum occurrences for warning totals. Declaration coverage remains partial
with its existing reason; dynamic ownership is still unknown.

`max_diagnostics` now bounds retained groups (unchanged default/ceiling 1,000),
so identical recoverable occurrences can exceed it. Parser errors and all other
classes retain individual admission. The encoded diagnostic array, including
JSON escaping, parser metadata and count growth, has an 8 MiB budget shared with
64 reserved bytes for a groups/occurrences summary. This adds no manifest space:
the existing complete-manifest and other resource limits still apply. Group and
total counts use checked unsigned 64-bit arithmetic; count/accounting overflow,
distinct-group or byte exhaustion refuses before publication. No truncation,
cap increase or successful-empty substitution is introduced. Explicit publication
rechecks diagnostic group/byte/count admission, including appended runtime
records; legacy implicit counts remain valid. No framework support, full-app
capacity, performance or launch qualification is established.

Reader opening independently validates saved diagnostic counts and budgets.
Check reports `diagnostics.groups` and `diagnostics.occurrences` separately.
