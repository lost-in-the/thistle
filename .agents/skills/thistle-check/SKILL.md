# Check

Use the [startup routing](../../../AGENTS.md#read-before-work) for applicable
policy sections; load specialist history only for the assigned question.

Read the [Auditor role](../../../docs/development/roles/auditor.md), the issue's
acceptance conditions and
[artifact policy](../../../docs/development/pr-ci-release.md#artifact-reuse-and-evidence).

1. Name the customer question, changed boundary, candidate and support scope.
   Separate development source checks, installed acceptance, protected
   qualification and publication authority.
2. Inventory existing evidence before execution. Read the actual retained
   artifacts/receipts; bind source, package, native observation, fixture,
   producer/consumer and generation identities where the declared contract
   requires them. A workflow success is not an unexamined payload audit.
3. Reuse `.github/scripts/pipeline.py verify`, `tools/check_install.rb` and the
   applicable existing journey/qualification drivers. A verifier establishes only
   its documented scope; source-build native bytes do not establish a separately
   loaded installed binary. Delegate repeatable comparisons to deterministic code.
4. Follow the affected user interaction: correct answer, source/ref links, pinned
   generation, explicit unavailable/partial/ambiguous results and failure paths.
   Include accessible Map interaction when the outcome changes it. Use the smallest
   meaningful checks and the task's resource allowance.
5. Report missing evidence as missing. Reuse unchanged evidence only for its
   applicable identities and scope; changed bytes require the affected gates.
   Before a retry or new workload, inspect prior results and task authority.
   Preserve one-shot/frozen restrictions and failed-attempt identities.
6. Return a scoped PASS, FAIL or INCONCLUSIVE with supporting receipts, limits,
   remaining obligation and owner. Keep optional improvements separate from
   acceptance blockers.

Do not silently acquire a host lease, rebuild packages, rerun a completed fixed
workload, change limits/evaluator policy or turn QA into release authority.
