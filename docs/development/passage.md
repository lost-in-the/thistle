# Selected-action potential Passage

LOS-150 answers one bounded question: for this saved route and **explicitly
selected action definition**, which registered filters, source operations,
potential model-save contribution and asynchronous/mail/template boundaries
should I inspect before changing behavior? This is source implementation awaiting
Root's independent source review and native/framework/installed/served checks.
Leah owns applicable acceptance. All 17 launch requirements remain unqualified.

```ruby
reader = Thistle::Reader.new(store, generation: saved_a)
begin
  choices = reader.passage(route_id) # items empty; no automatic first definition
  # The caller explicitly chooses one returned saved method identity.
  answer = reader.passage(route_id, action: chosen_id, limit: 8)
  # Continue with the same route, chosen action, generation and family.
  shared = reader.passage(route_id, action: chosen_id, family: 'export')
ensure
  reader.close
end
```

## Selection and meaning

Rust reuses the exact [route-action convention](route-actions.md). Original route
defaults, constraints, mount/redirect/dynamic uncertainty, capture coverage and
global ambiguity stay in the nested route component. An explicit action ID must
be an eligible saved instance method with that conventional owner/action key.
It can be one explicitly chosen syntax alternative; no runtime definition is
selected. A route with unsupported defaults cannot acquire an action sequence.
Inherited action resolution, custom inflection and true owner-declaration
resolution are not added. A method's `name_resolution` is never substituted for
its owner's declaration evidence.

Version 1 returns `generation`, compact route `root`, `selected_action` or null,
`selection_status`, `family`, original bounded `route` component, `items`,
`offset`, `coverage`, continuation and `semantics`. Compact witnesses use the
same generation/ID/kind/name/evidence/path/span shape as route-actions. Source
links use saved fact IDs and saved physical spans. No live source is consulted.

Without an action, `items` is empty and `selection_status` is
`choose_saved_action`; its scoped continuation pages the saved action choices,
without silently dropping candidates beyond the first page. Choosing an action
resets that cursor to the first sequence row. With an admitted action it is
`selected_syntax_binding_unknown`. Partial route discovery remains explicit even
when a caller selects one witnessed definition. Zero candidates and unsupported
forms retain the original route status; neither is exhaustive runtime absence.

Each list row is either a `controller_filter` or `source_operation`. The filter
prefix uses framework registration position, observed descriptor ownership,
shared-superclass identity and action applicability. The source suffix uses
lexical operation spans within only the chosen action body. These two orderings
are **not** a runtime chronology. Conditions remain unexecuted. Unknown rows do
not terminate later registration traversal. Nested declarations, blocks, lambdas,
helper/association/variable/relative-constant chains and unknown calls are explicit
boundaries. Parameters/default expressions are not parsed as action body steps.

The first supported save spelling is a direct root-qualified constant receiver
with `create` or `create!`, without safe navigation or an attached block. A
relative `Order.create!`, variable `.save!`, alias, helper return or association
chain is unsupported. Even supported syntax proves neither model identity nor
dispatch, validation, persistence or INSERT. Only that selected operation may
carry `save_contribution`. It requires exactly one saved `rails_model` label
candidate and one `rails_save_callbacks` label candidate to expose potential
callback contribution. Otherwise it explicitly reports
`qualified_target_unavailable`; it never inserts a generic lifecycle branch.

Qualified contribution reuses `callback_effects::select_scoped` and its existing
descriptor/source corroboration, ambiguity, omissions and shared work policy.
Its source-matched callback witnesses are exact edit locations, while
model-to-registry identity and runtime/source coherence remain unknown. A callback
with an opaque condition remains conditional. Save contribution does not imply
that the callback, its potential enqueue or anything downstream ran.

Root-qualified `perform_later` syntax stops at an asynchronous boundary.
Root-qualified constant calls may expose one related saved `Owner#method` label
candidate; duplicate/missing candidates stay unresolved. A typed existing
`job_mail/handoff` followup lets the investigator inspect mail/template source
beyond that **binding boundary**, separately from the asserted sequence. No
string is bridged into a continuous execution story. Delivery chains do not
establish mailer identity. Existing [job/mail/template](job-mail-template.md)
semantics own explicit template selection, saved ERB, dynamic/default refusals
and physical Source. Neither Ruby nor Map rebuilds those relationships.

## Explicit guarded controller observation

`Thistle.capture(..., rails: supplied_app, controller_filters: [OrdersController])`
opts in using explicitly loaded Classes and the supplied root/app. The default
and explicit nil keep the existing capture path. There is no descendant search,
autoload, application singleton getter, filter/action/condition execution or
application getter for the app. The new family supports the pinned Rails 8.1.4
layout; other layouts are unavailable.

The adapter reuses `CallbackObserver`'s guarded private class-attribute storage
leaf and builtin method descriptors. It reads the raw `process_action` chain,
preserving method/proc/opaque/unavailable descriptors and inherited ownership.
Rails action-filter objects expose only recorded `only`/`except` sets. Ruby 3.4's
exact Set backing Hash is read with bound builtins; Ruby 4's native Set requires
native `size` and `to_a` leaves (no Ruby override is dispatched). Other conditions
are opaque. Positive applicability means action metadata permits the registration,
never that a condition passed. `excluded_by_recorded_action_condition`,
`opaque_conditions_unknown` and
`action_applicable_conditions_not_executed` are distinct states.
The pinned [Rails 8.1.4 implementation](https://github.com/rails/rails/blob/v8.1.4/actionpack/lib/abstract_controller/callbacks.rb)
stores membership predicates in `if` for `only` and `unless` for `except`;
negation comes from that slot, not a second inversion of the option label.

Rust admits one strict `rails_controller_filters` runtime fact per explicit
controller. It validates closed version/provenance/row/descriptor/condition
shapes and recomputes the family identity. Unknown/anonymous controllers remain
rows. Source hints are root-relative only after safe lexical normalization;
outside-root, eval and unsafe hints become unavailable. A hint alone never creates
a Source URL: the selector must match a unique saved method descriptor/path/line.

Capture retains legacy **per-batch** `max_entries`. It does not recombine the walk
and all old metadata rows. Facts, links, diagnostic admission and encoded evidence
bytes use cumulative context and native delta charges. Earlier facts are not
reserialized for each new family. Explicit controller arrays copy at most 100,000
references before effective native limits are available; the observer then checks
remaining facts and charges controllers, registrations, conditions and action
labels against its unchanged batch allowance. Registry arrays are shallow-copied
once per distinct queried class/parent within this observer call and bounded
before copy; source hints and labels are primitive copies. No lifecycle watcher
or persistent registry cache is introduced.

## Work, continuation and alternatives

One passage operation reserves 96 MiB under the existing aggregate 128 MiB
query budget through native serialization, including the shared parser worker's
64 MiB stack and conservative source/AST/projection copies. The same process
permit controls parsing and destruction. Contention propagates typed Busy; Map
returns 503 and `Retry-After: 1`. The action worker completes before callback
explanation begins; no nested parser-worker permit acquisition is attempted.

The existing lazy method and recorded-name directories are reused, including
their separately admitted full-domain build/sort/retention costs and Reader-open
passes. No second full index, route-by-all-facts scan or persistent cursor cache
is added. The route selector's completed visits/comparisons/label bytes are first
charged into the same `RequestWork` used by later selection and scoped callback
explanation: at most 20,000 fact visits, 50,000 links, 100,000 comparisons, 32 MiB
labels, 16 source attempts, 1 MiB source and 8 MiB processed metadata. Existing
component caps remain. Exact route evidence is admitted before copy. Filter
applicability comparisons, file inventory selection, chosen fact projection,
Source validation links and callback copies also debit that shared work.

Only the selected saved method is parsed through the maintained Prism/child
walker and canonical saved-source validation. Whole-file size is at most 256 KiB;
the declaration slice is parsed in full **before** the 20,000 visited-node/200-row
extraction limits. Those are post-parse limits, not CPU/RSS limits. A bounded
partial scan carries `unsearched`; a complete scan omits it. Source order and
conditions stay explicit even for complete scans. Saved action source and parser
work repeat on each page; repeated prefix work is charged. Callback component
usage/omissions remain attached to that row. Source-derived budget values and
directory statistics are not measured heap, CPU, RSS or speed results.

Public limits are 1–16 rows and up to 64 KiB wire bytes including the native
success envelope and one byte of headroom. Map admits at most 8 rows/32 KiB,
possibly fewer for long full-collection links, under its unchanged 64 KiB display
budget. Mandatory-envelope/first-row overflow refuses rather than skipping a
row. Suffix cuts return the exact first unreturned ordinal. No zero-progress
self cursor is emitted. Source oversize, work or metadata exhaustion explicitly
refuses; it does not manufacture an empty successful analysis.

Continuation uses `recorded-v1` scope
`['passage', route_id, action_id_or_null, family]` and `[ordinal, 0]` on the exact
generation. Sequence and export are separate cursor scopes. `family: 'export'`
returns the identical typed items plus a bounded plain-text report containing
the same serialized items; it invents no alternate narrative. It exports only
this page; follow its same-family cursor for more. Map checks report consistency.

Reusing the route, callback, directory, Source, parser-worker and job/mail owners
keeps their semantics in one place. A Ruby resolver, generic lifecycle diagram or
regex save detector would create another authority and misattribute branches.
A persistent Passage index/cache would add capture schema, invalidation and
retention costs before a complete-job need is measured. The narrow Prism adapter
adds one bounded action-body interpretation without changing capture traversal.
No dependency is added to Core/Map. The fixture's Rails/SQLite dependencies reuse
the existing installed fixture cohort. The Core and Map packages include their
respective Passage contracts; shared decision and document-selector records keep
the existing contract union. This does not establish a package or installed pass.
