## Boundaries inspected

- **C/Rust ownership:** `ext/thistle_native/thistle_native.c:38` copies Ruby string bytes before releasing the GVL. The worker calls Rust using owned C memory, then `rb_ensure` at line 40 releases both buffers, including an exception on return or Ruby response construction. The Rust response uses one `CString::into_raw` and the matching `from_raw` release (`engine/src/lib.rs:110`, line 117). No borrowed Ruby objects are used by Rust workers. Allocation failure/OOM is not converted into guaranteed graceful refusal by these controls.
- **Reader lifecycle:** Constructor failure, post-native-open interruption, explicit close and finalizer paths are present. Registry storage uses `Arc`; a query retains its own reference while another thread closes its handle (`engine/src/lib.rs:19`, line 64). This supports memory lifetime safety during concurrent close, but does not promise cancellation or uninterrupted query completion.
- **JSON boundaries:** Incoming requests have a byte bound and depth validation (`engine/src/lib.rs:83`, line 85). Manifest depth and each stored fact are validated before exposure; metadata shape, digest, count, evidence category, path and source coordinates are checked. The 64-level payload policy and Ruby's 128-level response decoder agree for the response envelope.
- **Filesystem containment:** Store directory components use descriptor-relative `openat`, `O_DIRECTORY`, `O_NOFOLLOW` and `O_CLOEXEC` (`engine/src/fs.rs:42`); file opens add `O_NONBLOCK`, reject nonregular files and enforce bytes both before and during reading (lines 49–61). Capture pins ancestors and does not follow descendant symlinks (`engine/src/capture.rs:136`, line 151, line 225). Existing store files are trusted only as integrity-checked evidence; content digests do not authenticate the store's author.
- **Publication/recovery:** Validation precedes pointer replacement. Pre-pointer failures leave the previous pointer; post-pointer directory-sync failure returns `commit_uncertain` (`engine/src/store.rs:12`, line 94). Retention, storage quotas and power-loss recovery qualification remain open.
- **Fork behavior:** A process-ID guard precedes registry use (`engine/src/lib.rs:32`); inherited state is refused. This is a deliberate refusal, not general fork support.
- **CI:** The original development workflow uses read-only permissions, no `pull_request_target`, no persisted checkout credentials, immutable action references and no publication step (`.github/workflows/ci.yml:9`, lines 35–43). This review does not grant candidate-owned CI independent qualification authority.
