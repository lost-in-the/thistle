# Explore a saved model neighborhood

Open a recorded Rails model and choose **Model neighborhood**, **Columns** or
**Database facts** beside its heading. A static class is not assumed to be a
runtime model. The first neighborhood view immediately names related things in
a keyboard-accessible list. Its optional diagram shows the exact same selected
edge rows; names and evidence do not depend on JavaScript or guessing a zoom
threshold. Long names remain available in the primary list beside the diagram.

Switch Incoming/Outgoing and All recorded types/Associations/References with
visible links. Each edge gives its direction/type, original declaration or
recorded-link witness, source candidates and uncertainty. Unknown polymorphic
targets remain visible; missing targets may be unloaded or outside capture.
**Continue recorded rows** advances the native-selected domain. Candidate
continuation enumerates all saved representations without resolving the first
match. Counts are not distinct model-definition or execution counts.

Columns preserve raw typed defaults, SQL type and nullability. Literal false,
zero, empty and null differ from opaque/expression/unrecorded values; SQLite
may record strings for defaults of boolean/integer columns. Default clause
presence was not recorded. Physical database FKs, indexes and ON DELETE remain
unavailable; Rails foreign_key/dependent options do not establish those facts.

Source links use actual saved candidate IDs and physical spans in the pinned
generation. Return to the model with its search and collection context; a newer
CURRENT does not substitute its evidence. Dedicated pages validate generation,
model/family/filter/candidate/cursor before opening a Reader. Changing filters
resets continuation; Source sheds neighborhood controls. All 24 collection IDs,
the nine-field/4096-byte URL policy and visible atomic search-drop notice remain.

Each page makes one public Reader call. Map only presents the compact Rust DTO
and lays out the same list/diagram rows. It budgets repeated navigation hrefs and
dual label escaping before requesting data, then refuses explicit display
overflow above 64 KiB. No hidden graph-only row/label pruning, graph dependency,
new JavaScript, database query, Source selection reads or live target resolver is
added. Ordinary access/GET/HEAD/CSP/Reader-close behavior remains in App.

The list and optional finite server SVG reuse existing attributed Woods Map
presentation tokens; no Woods engine code is used. There is no whole-schema
ERD, multi-hop graph, cluster, history, Guide or export framework in this slice.
